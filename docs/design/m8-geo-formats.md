# M8 design: geo formats (GeoJSON, GeoPackage, GeoTIFF)

Status: agreed design for M8 (see [ROADMAP.md](../ROADMAP.md#m8-geo-formats-vectors-and-rasters-can-run-in-parallel-after-m2)).
Shared by the M8 work streams. Change it here first, then in code.

## Scope rule

GeoTools reads and writes the geo formats Blender cannot, in the project
frame, and keeps them linked to their files. Everything a user does with the
data inside Blender (draping on a mesh, offsetting by an attribute, extruding,
displacing) uses Blender's own tools, and is documented as a recipe. No
GeoTools node groups or modelling operators.

## Shared rules

- `geotools/core` never imports `bpy`. Parsing, writing, CRS matching and
  coordinate shifting live in `core` with pytest tests. Blender glue stays
  thin.
- Coordinates are binary64 until they become Blender float32 positions,
  relative to the project frame:
  `local = (E - offset_E, N - offset_N, Z - offset_A)` for a SOURCE_CRS
  project. LOCAL and ANCHOR projects take the data's coordinates as local
  metres, with a warning.
- Performance: no Python loops over vertices. A loop over *features* is
  acceptable where a format forces it (WKB records, polygon tessellation with
  `mathutils.geometry.tessellate_polygon`), but coordinates go into
  preallocated numpy arrays and reach the mesh with `foreach_set`. Target:
  100k polygon features in a few seconds.
- Fixtures are synthetic and generated by the tests (a GeoPackage via
  `sqlite3`, GeoJSON as text, a GeoTIFF from a minimal writer in the test
  fixtures). Never real site data.
- Import operators appear in File > Import (Blender convention) and in the
  GeoTools sidebar.

## CRS matching

`geotools/core/crs_match.py`:

```python
@dataclass(frozen=True, slots=True)
class DataCrs:
    epsg: str | None        # "EPSG:7856"
    definition: str | None  # WKT or PROJ text when there is no code
    source: str             # where it came from: "geojson-crs-member", "rfc7946-default", "gpkg-srs", "geotiff-geokeys", "user"

def project_crs(placement) -> DataCrs | None
def matches(project: DataCrs | None, data: DataCrs) -> bool | None   # None = can't tell
```

- GeoJSON: a legacy `crs` member if present; otherwise RFC 7946 WGS84
  (EPSG:4326).
- GeoPackage: the table's `srs_id` → `gpkg_spatial_ref_sys`
  (organization/organization_coordsys_id, definition).
- GeoTIFF: GeoKeys (ProjectedCSTypeGeoKey, GeographicTypeGeoKey).
- A mismatch is refused with a message that names both CRSs and suggests
  reprojecting in QGIS. When the CRS can't be determined, the user can confirm
  "data is in the project CRS".
- Reprojection: rusty-tiles has assessed a narrow `transform_points(xyz,
  from_crs, to_crs)` over its allow-listed CRSs as feasible for a 0.4.x
  release. It returns the points plus a report: operations per leg, the
  EPSG-stated accuracy, and the vertical handling. It goes through WGS84, so
  it reports or refuses pairs where a direct EPSG operation would be
  better. Keep one hook, `reproject(points, data_crs, project_crs)`, that
  raises "not available" today. When the function ships, the hook calls it
  and the import shows the reported accuracy. Points only: GeoTIFFs still
  need reprojecting in QGIS first.

## Vectors

### Reading and writing (`geotools/core/vector/`)

- `geojson.py`: FeatureCollection, Feature or bare geometry. Point,
  MultiPoint, LineString, MultiLineString, Polygon, MultiPolygon, and
  GeometryCollection (split by type). 2D and 3D.
- `gpkg.py` and `wkb.py`: read and write GeoPackage feature tables with the
  standard `sqlite3` module. GeoPackage binary header plus WKB/ISO WKB
  (Z, M ignored). Port and vectorise the legacy 0.2 reader and writer
  (`git show legacy-0.2:addons/data/gpkg/...`).
- One in-memory model, `VectorData`: per geometry kind (points, lines,
  polygons), the coordinates as float64 arrays with offsets (features → parts
  → rings), the feature ids, and the attribute columns (name → numpy array or
  a list of str, with a type).

### Blender representation

- One mesh object per source layer and geometry kind: `<layer>` for polygons,
  `<layer>.lines`, `<layer>.points` when a layer mixes kinds.
- Polygons → faces (an n-gon when it has no holes, tessellated triangles when
  it does); lines → loose edges; points → loose vertices.
- Attributes on the matching domain: FACE for polygons, EDGE for lines, POINT
  for points. Feature id `fid` (INT). Numbers → FLOAT or INT; booleans →
  BOOLEAN; text → STRING if Blender 5.2 supports string attributes on that
  domain, otherwise an INT code plus the label table in the link.
  Tessellated polygons repeat their feature's values on every triangle.
- Z kept when present (shifted by the project offset); 2D data gets z = 0.

### Linked sources

`GeoToolsLink` (PropertyGroup on `Object`, `obj.geotools_link`): `kind`
(GEOJSON, GPKG, GEOTIFF), `filepath`, `layer` (table or GeoJSON path),
`fid_field`, `crs` (the DataCrs as text), `options` (JSON: filters, geometry
kind, DEM decimation…), `fingerprint` (mtime_ns, size, sha256 for files under
64 MiB), `last_sync` (UTC ISO), `auto_refresh` (bool), `status`.

- **Refresh** re-reads with the stored options and replaces the object's mesh
  data in place (new mesh, swap, remove old), so modifiers, materials,
  transform, parent and layer links survive. One undo step. Reports added,
  removed and changed feature counts by fid.
- **Stale detection** on file load (`load_post` handler) and on demand,
  comparing the fingerprint. Cheap: stat first, hash only if stat changed.
- **Auto-refresh**: one `bpy.app.timers` timer for all linked objects, polling
  mtime every few seconds; refresh only when changed and not in Edit Mode.
- **Filters** (in `options`): a GeoPackage SQL `WHERE` (validated, read-only
  connection), and "within the site extent" (bbox of the source collection in
  project coordinates).
- **Attribute write-back** (GeoPackage): columns the user picks are written
  back by fid with `UPDATE` (adding columns if needed), in one transaction,
  refused if the fingerprint changed since the last sync. GeoJSON: rewrite the
  file, keeping unknown members and feature order. Geometry is never written
  back.

### Export

- Mesh → GeoJSON or GeoPackage with Z, from the evaluated mesh (modifiers
  applied, so a draped result exports with real heights), in the project CRS.
- Faces become polygons (with their attributes), loose edges become lines,
  loose vertices become points.
- GeoJSON in a projected CRS is outside RFC 7946. Write it with the legacy
  `crs` member and say so in the operator's tooltip.

### UI

A **Linked Data** panel after Source: a UIList of linked objects (icon by
kind, status icon: up to date, changed on disk, missing, error), Import
buttons (GeoJSON, GeoPackage, GeoTIFF), and for the selected link: Refresh,
Auto-refresh, filters, Write Back (GeoPackage), Export. Header status icon
like the other panels. Keep it compact; see `scripts/ui_screenshots.py`.

## GeoTIFF (`geotools/core/geotiff.py`, `geotools/blender/raster_io.py`)

Settled in work stream 2.

- **Tags** (`core/geotiff.py`, standard library and numpy): the first image
  (IFD) of a TIFF or BigTIFF, in either byte order. Size, samples per pixel,
  bits per sample, sample format, compression, predictor, planar
  configuration, strips or tiles; ModelPixelScale + ModelTiepoint or
  ModelTransformation; the GeoKeyDirectory (GTModelType, GTRasterType,
  ProjectedCSType, GeographicType, citations); GDAL_NODATA (42113).
  `read_info` returns a `GeoTiffInfo`.
- **Geotransform:** GDAL's `(x0, dx, 0, y0, 0, dy)` in binary64, always for
  pixel corners. A PixelIsPoint tiepoint names a pixel centre, so it is
  shifted by half a pixel, as GDAL does; the pixel centres then land exactly on
  the tiepoint grid. Rotated or sheared ModelTransformations and ground
  control points (several tiepoints) are refused, with "warp it to a north-up
  grid in QGIS". South-up rasters (dy > 0) are fine.
- **CRS:** ProjectedCSType or GeographicType gives `EPSG:n` (source
  `geotiff-geokeys`). A user-defined CRS (32767) gives a `DataCrs` with no
  code, and a file with no GeoKeys gives no CRS. Both need "Data is in the
  project CRS" to import. Geocentric files are refused.
- **Pixels** were checked against files from the test writer and from GDAL:
  - Blender's image loader (OpenImageIO, libtiff) reads float32 exactly, one
    band or more. That holds for uncompressed, deflate and LZW files, with the
    horizontal or floating-point predictor, in strips or tiles, classic or
    BigTIFF, in either byte order, and it keeps NaN and ±3.4e38. A 4096²
    float32 DEM loads in about 0.2 s.
  - Blender also reads uint8, uint16 and int16 exactly, normalised to float
    (÷255, ÷65535, ÷32767). `denormalise` rounds them back to the exact
    integers.
  - These four types go through Blender. The temporary image is set to
    Non-Color and channel-packed before its pixels are read, then removed.
  - Blender does not read float64 (rounded to float32) or int32 and uint32
    (low bits lost) exactly, and int8 and float16 were not checked. For those,
    `read_band` decodes the file with numpy: uncompressed or deflate (8 and
    32946), predictor 1, 2 or 3, strips or tiles, chunky or planar, with
    threaded zlib (0.16 s for a 4096² deflate DEM).
  - LZW with those types is refused, with "re-save as deflate or Float32". A
    pure-Python LZW decoder is far too slow for a DEM. `dem_route` picks the
    reader.
  - Palette images are refused as DEMs.
- **DEM → mesh** (`core/raster.dem_grid`, then `foreach_set`):
  - one vertex per sampled pixel centre, from the top-left pixel, every *n*
    pixels with decimation step *n*;
  - x and y are pixel centres in binary64 minus offset E/N, z is band 1 minus
    offset A, then float32;
  - quads, counter-clockwise from above (mirrored for south-up rasters);
  - faces touching a nodata or non-finite sample are dropped, and so are
    vertices no face uses;
  - one UV map, `UVMap`, spans the raster's pixel-edge extent (u = (col +
    0.5) / width, v = 1 − (row + 0.5) / height), so an orthophoto with the
    same extent maps onto it exactly;
  - the operator shows the resulting spacing and vertex count for the selected
    file;
  - positions and corner indices are written through the `position` and
    `.corner_vert` attributes, which Blender copies in one go. The
    `vertices`/`loops` `foreach_set` path is 180 to 380 times slower (1.8 s
    and 4.6 s against 0.01 s each at 4096²), and is kept only as a fallback.
  - Timing on the desktop (i7-12700KF) for a 4096² float32 DEM, deflate or LZW:
    16.8 M vertices, 16.8 M faces, 3.5 s in all (read 0.2 s, grid 1.1 s, mesh
    2.0 s, of which `calc_edges` is 1.3 s).
- **Orthophoto → image plane:** the image is a Blender image linked to the
  file, not packed, so the `.blend` stays small and Refresh is
  `Image.reload()`. Pack it yourself (File > External Data) to carry it in the
  `.blend`. One quad sits over the pixel-edge footprint at local z = 0, with
  UVs 0..1. Its material is a Principled BSDF with the image as base colour,
  roughness 1 and no specular; the alpha is linked when the file has an alpha
  band.
- **Automatic mode:** one band (or grey plus alpha) of floats or 16/32-bit
  integers is a DEM; anything else, including 8-bit grey, is an orthophoto.
  "As" overrides it.
- **CRS check** (`core/raster.check_crs`, on `crs_match`):
  - The CRS must match the project CRS. A mismatch is refused with a message
    that names both CRSs and suggests QGIS (Raster > Projections > Warp).
  - An unknown CRS needs "Data is in the project CRS".
  - LOCAL and ANCHOR projects import unshifted, with a warning.
  - Rasters are never reprojected.
- **Link:** `GeoToolsLink` kind GEOTIFF:
  - `options` is `{"mode": "DEM"|"ORTHO", "step": n, "assume_project_crs":
    bool}`;
  - `crs` holds the EPSG code (or the citation);
  - the fingerprint and `last_sync` are set on import and on refresh.
- **Refresh:** `raster_io.refresh(obj, link) -> RefreshReport` (`message`,
  `warnings`, `seconds`; `str()` is the message), for the Linked Data
  panel's Refresh to dispatch to when `kind == "GEOTIFF"`.
  - It re-reads with the stored options against the scene's current
    placement.
  - It builds a new mesh and swaps it in, keeping the mesh name and data
    materials, then removes the old mesh. Modifiers, object materials,
    transform, parent and collections are untouched. An orthophoto's image is
    reloaded.
  - It raises `ValueError` (`RasterError` or `GeoTiffError`) with a message,
    and sets the link status to MISSING or ERROR. On success the status is OK.
- **File > Import** has "GeoTIFF (.tif, .tiff)" (`geotools.import_geotiff`).
  The sidebar button is in the Linked Data panel (stream 1).

## Work streams

1. **Vectors:** `core/crs_match.py`, `core/vector/*`, import/export
   operators, `GeoToolsLink`, refresh, auto-refresh, filters, write-back, and
   the Linked Data panel.
2. **GeoTIFF:** `core/geotiff.py`, `blender/raster_io.py`, DEM and
   orthophoto import, linked refresh. It uses stream 1's `GeoToolsLink` and
   `crs_match` interfaces as written above. If stream 1 hasn't landed, create
   them as specified and expect a merge.
3. **Recipe:** docs and an example `.blend` (draping, offsetting by depth or
   level, extruding volumes), after stream 1.
